## Status vocabulary

- **PASS / COMPLETE:** only the cited, explicitly verified scope passed.
- **PARTIAL:** some planned capability has evidence, but the milestone is not fully closed.
- **OPEN:** unresolved issue retained for investigation.
- **DEFERRED:** intentionally not run or awaiting a prerequisite.
- **PLANNED:** future work; no result exists yet.
- **UNKNOWN:** current official or platform evidence does not answer the question.
- **BLOCKED:** work cannot proceed until the stated condition is addressed.

## M13 — Ross official information review

**Research date:** 2026-10-01. Sources below are AMD official product/download pages and AMD 2026.1 documentation. These establish product statements, not AI370-2 compatibility or test results.

### OFFICIAL CONFIRMED

- **Positioning and components:** AMD describes Ross as a client-agnostic natural-language assistant for AMD Embedded tool workflows, comprising MCP servers, AMD Knowledge Base, Agent Skills and design examples. AMD says MCP servers connect to supported embedded-tool sessions; Agent Skills encode structured workflows; examples provide tested reference designs.
- **MCP / tool operation:** Product material describes a knowledge-query path and a live tool-session path. It names Vivado and Vitis HLS in training/resources and says Vitis HLS Skills can use `v++` / `vitis-run` and source/project files directly without the MCP server. The current page FAQ states Vivado support for all versions and Vitis HLS support for 2025.2 and later.
- **Codex CLI:** AMD lists Codex CLI among compatible IDE/CLI options and describes the integration as client-agnostic when the client is compatible with MCP servers. This is an official compatibility statement, not a tested Codex-on-this-host result.
- **Knowledge Base / Skills / examples:** AMD documents searchable public documentation with cited answers; knowledge access can be cloud or local for supported environments. Agent Skills and design examples are published through AMD's Ross GitHub resources. Skills use `SKILL.md` and may be extended/created.
- **Account / license:** AMD says users sign in with AMD credentials to download MCP server executables. AMD says Ross itself requires no additional license; applicable AMD tool licenses remain necessary. The actual account entitlement needed for this host/download was not tested.
- **OS / requirements:** The official download page lists Windows and Linux MCP executables; the product page requires installed/licensed AMD tools and a compatible client plus a preferred LLM. It does not state an exact Ubuntu/kernel support matrix or hardware/RAM minimum for this host.
- **Versioning:** AMD states Ross has a monthly release cadence independent of Vivado/Vitis release cadence. At research time, AMD's downloads page exposed version `2026.9.1` Linux Vivado MCP and VS Code extension artifacts, with page-listed update date 2026-09-29. This is a dated catalog observation, not a selected or installed version.
- **Online/offline:** AMD describes online AMD Knowledge Base access. It also documents an air-gapped workflow: locally deploy the database with embedding model and MCP server, then use an answer-generation model fitting hardware/network policy. AMD does not thereby confirm that every Ross component, all tool control paths, or this AI370-2 configuration operates fully air-gapped.

### UNKNOWN

- Whether Ross MCP binaries support this exact Ubuntu 24.04.4 / kernel 6.17.0-14 host; AMD provides Linux downloads but the Ross page does not give a distro/kernel matrix.
- Exact Codex CLI version/configuration requirements, local endpoint compatibility, and whether Ross MCP/skills can use an existing local Qwen GGUF backend. AMD naming Codex CLI as compatible does not prove a particular local model route.
- Whether Ross directly controls Vitis Unified on this installation through Ross MCP. Vitis 2026.1 also documents its own Theia AI/MCP feature; that separate built-in feature must not be conflated with Ross.
- Which Ross MCP servers are available for each Vivado/Vitis/HLS operation, supported tool versions beyond explicit FAQ claims, offline package closure, ports, telemetry/network behavior and minimum resources until version-specific official docs or local tests confirm them.
- Whether air-gapped Ross setup allows a fully local answer-generation model with the proposed Codex CLI connection; AMD's general air-gapped workflow does not settle this client/model combination.

### PLANNED FOR VALIDATION

1. M13.1: obtain authorized Linux artifact, record exact version/hash/source; inspect host requirements before running; verify startup/version and uninstall/recovery path.
2. M13.2: connect compatible Codex CLI to Ross according to AMD's version-specific guide; prove client identity, MCP handshake and selected LLM provider. Do not assume local Qwen support.
3. M13.3: separately test Ross MCP with Vivado and relevant Vitis/HLS workflow; log tool invocation, command boundary, permission behavior and output. Treat native Vitis IDE AI as a separate path unless AMD documents interoperation.
4. M13.4: inspect skill provenance/version and Knowledge Base source/citation; test a read-only question and validate result against authoritative docs.
5. M13.5: after M11 enables physical board use, run a constrained SP701 workflow in a disposable project; require human review before synthesis/programming and verify generated artifacts independently.
6. M13.6: follow AMD's documented local database/embedding/MCP route and verify network isolation empirically; evaluate answer-generation model compatibility separately. No local/offline/air-gapped capability is claimed until tested.
