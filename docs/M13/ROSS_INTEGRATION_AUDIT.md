## Boundaries

- AMD Ross Skills are instruction files; they are not executable services and do not themselves run tools. In this integration the model must explicitly request `ross_skill_read` to receive the original selected Skill text.
- `vivado_doc_search` in the standalone Vivado MCP server is a hosted knowledge-base tool. The Local Agent instead talks directly to the existing local AMD Doc Search MCP, identified as `AMD Doc Search 0.11.0`, and only accepts a private endpoint. These are distinct MCP endpoints and are not conflated.
- The 13-tool Vivado MCP server is verified installed and discoverable over stdio MCP. Qwen does not receive arbitrary `vivado_execute` Tcl or server process control. Current RTL trials still use the existing fixed XSim runner. Thus this is genuine Ross Skill + local Knowledge Base MCP assistance, not Ross MCP-driven Vivado Tcl execution.
- No dedicated Vitis/HLS MCP was found in the installed MCP inventory. The Local Agent now has a separate bounded fixed `run_hls` executor; T3 demonstrates local Qwen + Ross HLS Skill/local KB source validation. This does not verify Vitis Unified/Embedded IDE control.
- The local KB endpoint is a current machine/container address and may change when its container network is recreated. It is explicitly provided at invocation; no Codex configuration file is read by Local Agent.
- The Local Agent can work with loopback model inference and network-isolated child tools. Full physical host disconnection and a licensed XSim run without host NIC visibility are not tested. Telegram still requires Telegram's Internet API.

## 2026-10-12/13 benchmark verification update

The complete formal T1/T2/T3 cohorts and exploratory T2 history are summarized in [the benchmark report](M13_ROSS_AB_BENCHMARK_REPORT.md); curated traces and SHA256 manifest are under [benchmark evidence](evidence/2026-10-12/ross-ab-benchmark/).

- **VERIFIED:** Every formal Ross B sample called the installed `vivado-simulate-rtl` Skill reader and the actual local AMD Doc Search MCP (`vivado_doc_search`). Server identity, responses, timestamps and trial results are in the JSONL traces. T3 Ross runs also used the installed HLS Skill and fixed local CSim/CSynth validator.
- **PASS, bounded:** Ross + local Qwen produced one accepted two-file T2 model-authored repair in corrected B1; after unchanged XSim baseline failure and two rejected patch formats, the fixed testbench passed. Corrected T2 B success is 1/3 versus A 3/3. T3 passed 3/3 in both arms.
- **FAIL:** T1 Ross repair passed 0/3 versus Non-Ross 3/3 because all B model repair outputs were invalid/truncated tool-call JSON. In corrected T2, B2 and B3 ended with provider context-length errors (8886 and 8919 tokens against 8192); source was not changed.
- **PARTIAL / no general benefit:** Completed A/B task success counts were T1 A3/3 B0/3; corrected T2 A3/3 B1/3; T3 A3/3 B3/3. Only T3 has balanced success for timing; Ross mean was 2.69% slower. Corrected T2 has only one B completion, so timing comparison is not meaningful.
- **NOT VERIFIED:** Qwen-driven Vivado Tcl via Vivado MCP; direct Vitis/HLS MCP (none found); full physical host disconnection; air-gapped Telegram/Ross operation. Loopback Qwen CPU and internal local KB calls do not prove a physically air-gapped configuration.

The benchmark verifies the Local Agent can use installed Ross Skills and the local Knowledge Base MCP. It does not establish a general success-rate or speed advantage, nor does it expose arbitrary Vivado Tcl to Qwen. M13 remains PARTIAL.
